# Quilt v0.6.0

_Released 2026-11-21 · [all releases](../release-notes.md)_

The largest release so far: three new languages, a hand-written Quilt parser, *machines* and live notebooks, new demos, and a conformance harness that checks every support claim in CI.

## New languages

- **Lean 4**, as both a quotable target and a string-based host, with LSP support on both sides. Spliced host text is laid out at its hole's column, so generated Lean keeps its indentation-sensitive structure ([#139](https://github.com/QuiltLang/quilt/pull/139), [#301](https://github.com/QuiltLang/quilt/pull/301), [#312](https://github.com/QuiltLang/quilt/pull/312)). Lean examples cover do-notation, datatypes and tactic proofs ([#146](https://github.com/QuiltLang/quilt/pull/146)).
- **SQL** as a target. Values cross in through `↑` as literal nodes, not text, so a lifted value cannot escape its literal. The escaping dialect is chosen by annotation, and a hole can stand for a whole statement ([#236](https://github.com/QuiltLang/quilt/pull/236), [#243](https://github.com/QuiltLang/quilt/pull/243), [#245](https://github.com/QuiltLang/quilt/pull/245)).
- **Nix** as a target and as a string-based host, with emit `←` implemented as a functional join ([#69](https://github.com/QuiltLang/quilt/pull/69), [#70](https://github.com/QuiltLang/quilt/pull/70), [#187](https://github.com/QuiltLang/quilt/pull/187)).
- **TypeScript, HTML and plain text** can now be lift targets, with text dialects ([#313](https://github.com/QuiltLang/quilt/pull/313)). TypeScript gains a functional `←`, and primitives splice as text ([#318](https://github.com/QuiltLang/quilt/pull/318)).
- **bash and zsh** are now string-based hosts, so their hashbang is reachable ([#224](https://github.com/QuiltLang/quilt/pull/224)).

## Machines and notebooks

- **Machines**: stateful evaluators that complete the Language / MetaLanguage square. A machine is fed fragments over time, keeps its definitions, and answers queries with the literal spelling of the value ([#262](https://github.com/QuiltLang/quilt/pull/262)). This release adds a Lean machine, `ForkMachine` for live siblings, and pinned machines with identity, a cleared environment and Nix content addresses ([#287](https://github.com/QuiltLang/quilt/pull/287), [#307](https://github.com/QuiltLang/quilt/pull/307)).
- **[Notebooks](../notebook.md)**: an `.html.quilt` page whose cells run on machines ([#276](https://github.com/QuiltLang/quilt/pull/276)), plus live notebooks with an editor, the running page, and a site built from inside it ([#279](https://github.com/QuiltLang/quilt/pull/279)).

## New demos and examples

The website has a new [Demos](https://quiltlang.github.io/demos/) gallery. Demos now live at top-level URLs, and the old `/demo/` links redirect.

- **[Phib](https://quiltlang.github.io/phib/)**: a language for cellular automata where every rule is a picture of cells before and after. You can play its frog puzzles, redraw the rules, and race three engines. Its JavaScript and WGSL compilers are written in Quilt ([source](https://github.com/QuiltLang/phib)).
- **[Browser Playground](https://quiltlang.github.io/playground/)**, rebuilt as a three-stage live dashboard: TypeScript that generates TypeScript that generates HTML. Edit the schema or the `.quilt` source and the WebAssembly expander re-runs every stage in the browser, including `↓` ([source](https://github.com/QuiltLang/quiltlang.github.io/blob/main/docs-site/static/playground/dashboard.html.ts.ts.quilt)).
- **[Polyglot Notebook](https://github.com/QuiltLang/quilt/blob/main/examples/notebook/tour.html.quilt)**: an HTML page that is also the program. Python, SQL, shell and Node cells are quotes spliced into the page, each run on a persistent machine, and `quilt notebook` writes their output back in.
- **[metaarch](https://github.com/QuiltLang/metaarch)**: a distributed-system compiler built on Quilt. One `.arch` file describes services, databases and events, and it generates Rust and Python services, SQL schemas, clients, tests, docs and a Nix deployment.
- **New examples** in [`examples/`](https://github.com/QuiltLang/quilt/tree/main/examples):
  - Lean: `lean_datatypes`, `lean_do_pipeline`, `lean_specialize`, `lean_tactics`, `lean_host`
  - SQL: `sql_query`, `sql_session`
  - Nix: `nix_module`, `nix_emit`, `nix_host`
  - Staged code generation: `staged_pow` in Python and TypeScript, `web/dashboard`
  - Notebooks: `notebook/tour`, `notebook/cafe`
  - Also: `config_gen`, `db_menu`, `shell_host`

## Core language

- **Hand-written Quilt parser.** The surface syntax is now scanned directly instead of going through tree-sitter-quilt, which is faster and reports malformed syntax as an error instead of panicking. The `tree-sitter-quilt` grammar is gone, and the language server uses the new parser ([#175](https://github.com/QuiltLang/quilt/pull/175), [#255](https://github.com/QuiltLang/quilt/pull/255)).
- **Staging.** `↑` is deferred inside unresolved quotes, so multi-stage programs show the lift at the right stage ([#73](https://github.com/QuiltLang/quilt/pull/73)). `↓` (reduce) is glyph-aware and block-aware ([#74](https://github.com/QuiltLang/quilt/pull/74)), and has a native Node runner for `.ts.quilt` ([#198](https://github.com/QuiltLang/quilt/pull/198)). Lift now satisfies `reduce(lift(x)) == x` in all three runtimes ([#173](https://github.com/QuiltLang/quilt/pull/173)).
- **Prelude injection.** Expanded files open with their runtime import, so `.quilt` sources no longer type it by hand ([#275](https://github.com/QuiltLang/quilt/pull/275)).
- **Quote representations.** `ts⟨str⟩↖…↗` and `ts⟨qt⟩↖…↗` pick how a quote is represented ([#322](https://github.com/QuiltLang/quilt/pull/322)). A bare quote inherits its annotated sibling's language ([#317](https://github.com/QuiltLang/quilt/pull/317)), and a quote may be a fragment rather than a whole file ([#319](https://github.com/QuiltLang/quilt/pull/319)) or the whole body of a closure ([#247](https://github.com/QuiltLang/quilt/pull/247)).
- **Holes.** A hole need not be a whole word ([#231](https://github.com/QuiltLang/quilt/pull/231)). In Rust, a hole can stand for items, variants, fields, match arms, item names, pattern paths, pattern fields and path segments ([#309](https://github.com/QuiltLang/quilt/pull/309), [#323](https://github.com/QuiltLang/quilt/pull/323)). An unquote inside a quoted comment takes a hole ([#298](https://github.com/QuiltLang/quilt/pull/298)), and a splice of several elements is separated into a comma-separated list ([#311](https://github.com/QuiltLang/quilt/pull/311)).
- **Escaping.** `←` is escapable and the full glyph set re-escapes ([#142](https://github.com/QuiltLang/quilt/pull/142)). Terms render back to `.quilt` source, escapes included ([#232](https://github.com/QuiltLang/quilt/pull/232)).
- **Layout.** Indented quote bodies are dedented by their own indent ([#76](https://github.com/QuiltLang/quilt/pull/76), [#296](https://github.com/QuiltLang/quilt/pull/296), [#316](https://github.com/QuiltLang/quilt/pull/316)), and flush-left lines in multi-line strings are kept verbatim ([#292](https://github.com/QuiltLang/quilt/pull/292)).
- **Generated-file header.** The header is written as a comment in the target language, derived from the language registry, and no longer depends on the path passed to `expand` ([#138](https://github.com/QuiltLang/quilt/pull/138), [#170](https://github.com/QuiltLang/quilt/pull/170), [#299](https://github.com/QuiltLang/quilt/pull/299)).

## Runtimes and tooling

- **`quilt-wasm`** builds terms as plain JavaScript objects and calls into wasm only where Rust logic is needed ([#308](https://github.com/QuiltLang/quilt/pull/308)). The in-browser expander injects the runtime import, and the browser demos run in CI ([#315](https://github.com/QuiltLang/quilt/pull/315)).
- **`quilt-lsp`**: Python diagnostics re-enabled through a typed ground prologue ([#145](https://github.com/QuiltLang/quilt/pull/145)).
- **CLI**: `quilt run` resolves the interpreter from the shebang ([#178](https://github.com/QuiltLang/quilt/pull/178)), and `quilt check` validates extension-less shebang scripts ([#220](https://github.com/QuiltLang/quilt/pull/220)).
- Python: an in-process expander with `expand` / `run` ([#71](https://github.com/QuiltLang/quilt/pull/71)).

## Conformance and testing

- A **conformance harness** verifies every capability claim and generates the [Support Matrix](../support-matrix.md); a claim that stops being true fails CI ([#147](https://github.com/QuiltLang/quilt/pull/147), [#148](https://github.com/QuiltLang/quilt/pull/148), [#163](https://github.com/QuiltLang/quilt/pull/163)).
- A cross-language grid tests every host against every target ([#169](https://github.com/QuiltLang/quilt/pull/169)), and a runtime parity corpus covers the three published runtimes ([#168](https://github.com/QuiltLang/quilt/pull/168)).
- Snapshot tests for expander output, a grammar corpus for the surface syntax, a `tests/ui/` diagnostic corpus, property-based and fuzz testing, and a nightly coverage job ([#164](https://github.com/QuiltLang/quilt/pull/164), [#165](https://github.com/QuiltLang/quilt/pull/165), [#210](https://github.com/QuiltLang/quilt/pull/210), [#214](https://github.com/QuiltLang/quilt/pull/214), [#242](https://github.com/QuiltLang/quilt/pull/242)).
- Arity tables, lift shapes and comment syntax are derived from the grammars instead of written by hand ([#207](https://github.com/QuiltLang/quilt/pull/207), [#235](https://github.com/QuiltLang/quilt/pull/235), [#249](https://github.com/QuiltLang/quilt/pull/249)).

## Breaking changes

- **`tree-sitter-quilt` is no longer published.** Editors and tools that used it for highlighting should use `quilt-lsp` ([#255](https://github.com/QuiltLang/quilt/pull/255)).
- **`quilt-wasm`'s JavaScript API changed.** Terms are now plain JS objects built by `quilt-wasm/js/runtime.js` rather than wasm handles ([#308](https://github.com/QuiltLang/quilt/pull/308)). Re-expand `.ts.quilt` files with this release.
- **Ground `←` is rejected in the Python and TypeScript hosts** ([#209](https://github.com/QuiltLang/quilt/pull/209)). String-based hosts (Nix, Lean) also fail loudly on operator glyphs they do not support, instead of emitting broken code ([#143](https://github.com/QuiltLang/quilt/pull/143)).
- **Expanded output changed.** Because of prelude injection, the new header format and the dedent fixes, regenerated files differ from v0.5.0 output. A source that already imports the runtime keeps its own import; `--no-prelude` turns injection off. `expand` no longer copies a source's shebang into the output ([#275](https://github.com/QuiltLang/quilt/pull/275)).
