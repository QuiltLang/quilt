## Notes and limitations

### Bash

- 🟡 **Variadic** — the arity table has drifted from zsh's despite the two being documented as equivalent: bash lists `variable_assignment`, `for_statement`, `while_statement` and `function_definition`, which zsh's table omits ([#144](https://github.com/QuiltLang/quilt/issues/144))
- ⬜ **Kinds** — no `typ()` override, so every tag reports the default `File`
- 🟡 **Lift in** — strings and integers only — the shells are word-oriented, so there is no float or bool `LiftTo<Bash>` impl ([#144](https://github.com/QuiltLang/quilt/issues/144))
- ⬜ **Host** — target-only: no `MetaLanguage`, so the host's meta drives expansion
- ⬜ **Lift out** — target-only: nothing to lift from
- ⬜ **Reduce ↓** — target-only: no meta-language to reduce with
- ⬜ **Emit ←** — target-only: `←` is the *host's* operator, so this language has no emit of its own. What matters for a target is having variadic containers to receive emitted children, which is the Variadic axis
- ⬜ **Patterns** — target-only; bash fragments can still be destructured by a Rust host
- 🟡 **Runnable** — `hashbang()` returns `#!/usr/bin/env bash`, but bash has no `MetaLanguage` so it can never be a ground language — the shebang is unreachable through `quilt run` ([#144](https://github.com/QuiltLang/quilt/issues/144))
- ⬜ **Runtime** — target-only: no runtime library
- ⬜ **Header** — target-only: never the ground language, so no generated-file header is produced
- 🟡 **LSP** — embedded-quote highlighting only, from the vendored `highlights.scm`; no downstream bash server is proxied ([#144](https://github.com/QuiltLang/quilt/issues/144))

### HTML

- ⬜ **Kinds** — no `typ()` override, so every tag reports the default `File`
- 🟡 **Lift in** — no `LiftTo<Html>` marker, so a Rust host cannot lift into an HTML quote; the Python and TypeScript hosts lift through `qlift_html` instead, which is a host-side spelling rather than a `LiftTo` impl ([#144](https://github.com/QuiltLang/quilt/issues/144))
- ⬜ **Host** — target-only: no `MetaLanguage`, so the host's meta drives expansion
- ⬜ **Lift out** — target-only: nothing to lift from
- ⬜ **Reduce ↓** — target-only: no meta-language to reduce with
- ⬜ **Emit ←** — target-only: `←` is the *host's* operator, so this language has no emit of its own. What matters for a target is having variadic containers to receive emitted children, which is the Variadic axis
- ⬜ **Patterns** — target-only; HTML fragments can still be destructured by a Rust host
- ⬜ **Runnable** — a document is rendered by a browser, not executed
- ⬜ **Runtime** — target-only: no runtime library
- ⬜ **Header** — target-only: never the ground language, so no generated-file header is produced
- 🟡 **LSP** — embedded-quote highlighting only, from the vendored `highlights.scm`; no downstream HTML server is proxied ([#144](https://github.com/QuiltLang/quilt/issues/144))

### Lean 4

- 🟡 **Holes** — term, tactic, do-element, declaration-name and binder position all work with the unpatched grammar (`__QUILT_HOLE__` matches Lean's identifier regex); whole-command position is reached only by the `#check …` wrapper fallback in `parse_pre` ([#133](https://github.com/QuiltLang/quilt/issues/133))
- ⬜ **Reduce ↓** — no reduce backend: the string-based meta has no `QTerm` runtime to evaluate against ([#132](https://github.com/QuiltLang/quilt/issues/132))
- ⬜ **Emit ←** — `emit_str` fails unconditionally: the string-based meta has no `b_` accumulator for `←` to append to, and the error points at `List.map` + `String.intercalate` instead. Automatic emission of children into the variadic `by` / `do` containers is a separate mechanism (`wrap_child`) and is unaffected; a top-level sequence of commands additionally needs a variadic `module` ([#133](https://github.com/QuiltLang/quilt/issues/133))
- ⬜ **Patterns** — no `pattern_tag`/`pattern_var` implementation; Lean fragments can still be destructured by a Rust host
- ⬜ **Runnable** — Lean has no interpreter shebang — a file runs via `lean file.lean` or `lake env lean`, and `#!` is not Lean comment syntax
- ⬜ **Runtime** — string-based meta: no `QTerm` runtime library is shipped for Lean ([#132](https://github.com/QuiltLang/quilt/issues/132))
- 🟡 **Glyphs** — `←` is Lean's monadic bind and is eaten by the emit glyph; `↑` (coercion) and `↓` (lowering) are also real Lean notation. The ASCII alias `<-` is the current workaround, and `\←` does not escape because `←` is missing from the grammar's escape class ([#141](https://github.com/QuiltLang/quilt/issues/141))

### Nix

- ⬜ **Reduce ↓** — no reduce backend: the string-based meta has no `QTerm` runtime to evaluate against ([#132](https://github.com/QuiltLang/quilt/issues/132))
- ⬜ **Emit ←** — `emit_str` fails unconditionally: the string model has no `b_` accumulator for `←` to append to. Build sequences functionally with `map` / `concatStringsSep`, which is what the error says ([#132](https://github.com/QuiltLang/quilt/issues/132))
- ⬜ **Patterns** — no `pattern_tag`/`pattern_var` implementation; Nix fragments can still be destructured by a Rust host
- ⬜ **Runnable** — a `.nix` file is evaluated with `nix eval`, not executed, so there is no shebang runner
- ⬜ **Runtime** — string-based meta: no `QTerm` runtime library is shipped for Nix ([#132](https://github.com/QuiltLang/quilt/issues/132))
- 🟡 **LSP** — embedded-quote highlighting only, from the vendored `highlights.scm`; no downstream Nix server is proxied ([#144](https://github.com/QuiltLang/quilt/issues/144))

### Python

- 🟡 **Emit ←** — no statement-splice: the fluent `.e(child)` chain has no named `b_` accumulator the way the Rust variadic block does, so emit from a ground loop is unavailable ([#144](https://github.com/QuiltLang/quilt/issues/144))
- ⬜ **Patterns** — `PythonMetaLanguage` sets no `pattern_tag`, so a Python host cannot write `let ↖…↗ = …`. Python *fragments* can still be destructured by a Rust host, which is what `expand_rust.rs::pattern_let_runtime` exercises

### Rust

- ⬜ **Highlights** — the LSP projects Rust to rust-analyzer rather than highlighting it from a vendored query

### Plain text

- ⬜ **Lift in** — no `LiftTo<Text>` marker; a host that wants a value as text lifts it in its own language and splices the result ([#144](https://github.com/QuiltLang/quilt/issues/144))
- ⬜ **Highlights** — plain text has no grammar to highlight
- ⬜ **Host** — the `TextMetaLanguage` exists but is identity-only and is not registered as a host in `Omni`
- ⬜ **Lift out** — not a host: nothing to lift from
- ⬜ **Reduce ↓** — not a host: no meta-language to reduce with
- ⬜ **Emit ←** — target-only: `←` is the *host's* operator, so this language has no emit of its own. What matters for a target is having variadic containers to receive emitted children, which is the Variadic axis
- ⬜ **Patterns** — target-only; text fragments can still be destructured by a Rust host
- ⬜ **Runnable** — plain text is not executable
- ⬜ **Runtime** — target-only: no runtime library
- ⬜ **Header** — target-only: never the ground language, so no generated-file header is produced
- ⬜ **LSP** — nothing to project: plain text has no downstream server

### TypeScript

- ⬜ **Lift in** — no `LiftTo<TypeScript>` marker in `lift.rs`, so a Rust host cannot lift a value into a TypeScript quote; the TypeScript host lifts its own values through the wasm runtime's `qlift` ([#144](https://github.com/QuiltLang/quilt/issues/144))
- ⬜ **Highlights** — no `highlights.scm` is vendored for the TypeScript grammar
- 🟡 **Reduce ↓** — `↓` runs in the browser demo via the WASI expander rather than a native runner, so there is no `quilt run` reduce backend ([#144](https://github.com/QuiltLang/quilt/issues/144))
- 🟡 **Emit ←** — same fluent-chain shape as Python: no named accumulator, so emit from a ground loop is unavailable ([#144](https://github.com/QuiltLang/quilt/issues/144))
- ⬜ **Patterns** — no `pattern_tag`/`pattern_var` implementation; pattern lets are a Rust-host feature
- ⬜ **LSP** — no `LanguageAdapter`; `.ts.quilt` files get no projection

### WGSL

- ⬜ **Kinds** — no `typ()` override, so every tag reports the default `File`; WGSL instead sorts fragments with `classify_term`, which reads the parsed term rather than the tag
- 🟡 **Lift in** — numeric and bool literals only — WGSL has no string type, so no `LiftTo<Wgsl> for str` impl exists and lifting a string is a compile error in the generated program rather than a silent truncation. 64-bit integers are likewise omitted ([#144](https://github.com/QuiltLang/quilt/issues/144))
- ⬜ **Highlights** — the LSP vendors a patched WGSL highlight query of its own rather than exposing one from `quilt::grammars` ([#22](https://github.com/QuiltLang/quilt/issues/22))
- ⬜ **Host** — target-only: no `MetaLanguage`, so the host's meta drives expansion
- ⬜ **Lift out** — target-only: nothing to lift from
- ⬜ **Reduce ↓** — target-only: no meta-language to reduce with
- ⬜ **Emit ←** — target-only: `←` is the *host's* operator, so this language has no emit of its own. What matters for a target is having variadic containers to receive emitted children, which is the Variadic axis
- ⬜ **Patterns** — target-only; WGSL fragments can still be destructured by a Rust host
- ⬜ **Runnable** — a shader is compiled by the host application, not executed directly
- ⬜ **Runtime** — target-only: no runtime library
- ⬜ **Header** — target-only: never the ground language, so no generated-file header is produced
- 🟡 **LSP** — embedded-quote highlighting only, from the LSP's vendored query ([#22](https://github.com/QuiltLang/quilt/issues/22))

### Zsh

- 🟡 **Variadic** — the arity table has drifted from bash's: zsh omits `variable_assignment`, `for_statement`, `while_statement` and `function_definition`, so an emit into a zsh `for` body behaves differently from the identical bash one ([#144](https://github.com/QuiltLang/quilt/issues/144))
- ⬜ **Kinds** — no `typ()` override, so every tag reports the default `File`
- 🟡 **Lift in** — strings and integers only — the shells are word-oriented, so there is no float or bool `LiftTo<Zsh>` impl ([#144](https://github.com/QuiltLang/quilt/issues/144))
- ⬜ **Host** — target-only: no `MetaLanguage`, so the host's meta drives expansion
- ⬜ **Lift out** — target-only: nothing to lift from
- ⬜ **Reduce ↓** — target-only: no meta-language to reduce with
- ⬜ **Emit ←** — target-only: `←` is the *host's* operator, so this language has no emit of its own. What matters for a target is having variadic containers to receive emitted children, which is the Variadic axis
- ⬜ **Patterns** — target-only; zsh fragments can still be destructured by a Rust host
- 🟡 **Runnable** — `hashbang()` returns `#!/usr/bin/env zsh`, but zsh has no `MetaLanguage` so it can never be a ground language — the shebang is unreachable through `quilt run` ([#144](https://github.com/QuiltLang/quilt/issues/144))

- ⬜ **Header** — target-only: never the ground language, so no generated-file header is produced
